01

Separate three testing levels

Unit tests call our graders and hooks without a model. Integration checks one real query and its wiring. Evals repeat realistic tasks and measure outcomes.

02

Version cases and fixtures

Each case declares a fixed prompt, optional JSON schema, expected outcome and grader. Every real run copies the versioned fixture into a new temporary workspace.

03

Grade facts and side effects

Validate native structured output against actual expected fields. Independently run trusted fixture tests after validating all permitted source changes. A fluent success message is not a passing grade.

04

Repeat and report

Repeated runs use fresh workspaces. Inspect per-case pass rate, estimated cost, turns and a Wilson interval. Three classroom samples cannot establish production reliability.

05

Keep failures visible

Negative controls intentionally fail: an incorrect expected count, an unchanged buggy fixture, a one-turn run and a suite with a failing case. Preserve native results and failed grades.

06

Gate changes with evidence

Require each case to reach the 80% observed pass threshold. Keep missing cost fields unknown, retain a JSONL record per run and compare reports with model, prompt and fixture provenance.
